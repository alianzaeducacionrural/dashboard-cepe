1. Resumen ejecutivo

El aplicativo web "La Universidad en el Campo" es una herramienta digital de seguimiento, monitoreo y gestión creada para el equipo CEPE y el Comité de Cafeteros de Caldas. Su propósito es centralizar, visualizar y administrar toda la información de la iniciativa: objetivos, productos, actividades, indicadores MEL, beneficiarios, finanzas, talento humano y alertas, con una interfaz visualmente atractiva, dinámica e interactiva.

El sistema funciona como tablero público de consulta (sin login) y como panel interno de gestión (protegido por contraseña simple) para que el equipo CEPE pueda cargar y actualizar información.

Arquitectura

  • Frontend: HTML5 + CSS3 + JavaScript (migrable a React + Vite + TypeScript) alojado en GitHub Pages.
  • Backend: Google Apps Script (GAS) desarrollado con clasp, almacenado en la carpeta institucional de Google Drive.
  • Base de datos: Google Sheets (gestionado desde Apps Script).
  • Comunicación: Web App de Apps Script publicada como API REST → consumida vía fetch desde el frontend.
📁 Carpeta institucional de Drive: https://drive.google.com/drive/folders/1rgOSvr9fmi0sSieOndXpge9aY4vszU3I

2. Contexto y justificación

La iniciativa La Universidad en el Campo es liderada por el Comité de Cafeteros de Caldas bajo el enfoque de articulación educación media – posmedia, liderazgo directivo y fortalecimiento de la triada Familia–Escuela–Estudiante, en el marco del programa Comunidades de Cambio – CEPE.

Actualmente la información vive dispersa en múltiples archivos: Excel de cronograma, informes PDF, presentaciones, matrices financieras, listados de beneficiarios y matrices MEL. Esto dificulta:

  • Ver el avance consolidado en tiempo real.
  • Detectar retrasos y alertas tempranas.
  • Comparar lo planeado vs. lo ejecutado.
  • Reportar a Fundación PLAN y a la Secretaría de Educación de Manizales.
  • Tomar decisiones oportunas.

El aplicativo resuelve esto con un sistema único, visual y accesible, que consolida toda la información en un solo lugar, muestra semáforos y alertas automáticas, permite actualizar avances desde la app, genera reportes exportables (PDF, Excel), es público para consulta y privado para edición.

3. Objetivos del aplicativo

Objetivo general

Diseñar y desarrollar un aplicativo web que permita visualizar, gestionar y monitorear el avance técnico, financiero y territorial de la iniciativa "La Universidad en el Campo", mediante un dashboard interactivo y un panel de administración integrado con Google Sheets.

Objetivos específicos

  1. Centralizar la información del proyecto (objetivos, productos, actividades, indicadores, beneficiarios, finanzas, talento humano).
  2. Visualizar el avance por objetivo, producto y actividad con semáforos y KPIs dinámicos.
  3. Generar alertas automáticas por retrasos en productos e indicadores MEL sin medir.
  4. Permitir la carga y edición manual de la información desde la app.
  5. Exportar reportes en PDF y Excel para rendición de cuentas.
  6. Facilitar la toma de decisiones con datos consolidados y actualizados.
  7. Ser accesible públicamente para consulta y auditable en su versión de solo lectura.

4. Alcance

Incluye

  • Dashboard general con KPIs, semáforos y alertas.
  • Módulo de productos con filtros, búsqueda y edición.
  • Cronograma tipo Gantt mensual (marzo – noviembre).
  • Módulo de indicadores MEL con estado de medición.
  • Módulo de beneficiarios (estudiantes, docentes, directivos).
  • Módulo financiero (presupuesto vs. ejecución, por objetivo y fuente).
  • Módulo de instituciones educativas (12 IEs rurales de Manizales).
  • Módulo de talento humano.
  • Módulo de alertas centralizadas.
  • Panel de administración con formularios de carga.
  • Exportación a PDF y Excel.
  • Modo claro / oscuro.
  • Identidad visual CEPE.

No incluye (por ahora)

  • Login con usuarios y roles (se usará contraseña simple en admin).
  • Notificaciones push o por correo automáticas.
  • App móvil nativa.
  • Integración directa con sistemas externos (SED, universidades).
  • Firma electrónica o flujos de aprobación.

Flujo de datos

  1. Lectura (público): Frontend → fetch(GAS_URL?action=getAll) → Apps Script lee Sheets → devuelve JSON → Frontend renderiza.
  2. Escritura (admin): Admin ingresa contraseña → frontend envía POST con token → Apps Script valida → escribe en Sheets → responde OK.
  3. Alertas: Apps Script recalcula alertas cada vez que se leen o escriben datos, aplicando reglas de negocio.

13. Integración frontend ↔ backend

13.1 Configuración

const GAS_URL = "https://script.google.com/macros/s/AKfycb.../exec";

13.2 Ejemplo de lectura

async function cargarDashboard() {
  const res = await fetch(`${GAS_URL}?action=getDashboard`);
  const json = await res.json();
  if (!json.ok) throw new Error(json.error);
  renderDashboard(json.data);
}

13.3 Ejemplo de escritura

async function actualizarProducto(id, cambios, token) {
  const res = await fetch(GAS_URL, {
    method: "POST",
    body: JSON.stringify({ action: "updateProducto", id, cambios, token }),
  });
  return await res.json();
}

13.4 CORS

Apps Script Web App publicada como ANYONE_ANONYMOUS permite CORS desde cualquier origen si se usa ContentService con JSON. Se documentará esta configuración en el README del backend.

14. Seguridad y control de acceso

  • Frontend público: sin login, solo lectura.
  • Panel admin: protegido por contraseña simple almacenada como variable de entorno en Apps Script (PropertiesService).
  • Token temporal: al validar la contraseña, el backend devuelve un token temporal guardado en CacheService (expira en 30 min).
  • Validación en backend: cada operación de escritura valida el token.
  • Sin datos sensibles: no se almacenan datos personales sensibles; solo información agregada del proyecto.
  • Auditoría: cada escritura registra usuario (rol), fecha y cambios en una hoja LOGS.

  5. Copiar la URL /exec y usarla en el frontend.

16.2 Frontend

  1. Repositorio en GitHub: ucampo-dashboard.
  2. Configurar GitHub Pages desde Settings → Pages.
  3. CI/CD opcional con GitHub Actions: cada push a main compila y publica.
  4. URL pública: https://<usuario>.github.io/ucampo-dashboard/.

17. Plan de trabajo por fases

Fase 0 – Preparación

  • Crear carpeta de Drive y subcarpetas.
  • Instalar clasp y autenticar.
  • Crear Sheet backend y ejecutar script de estructura.
  • Crear repositorio GitHub.
  • Configurar GitHub Pages.

Fase 1 – Prototipo visual

  • Maquetar dashboard en HTML/CSS/JS.
  • Validar diseño con el equipo.
  • Ajustar identidad visual.

Fase 2 – Backend Apps Script

  • Desarrollar servicios (lectura y escritura).
  • Implementar reglas de semáforos y alertas.
  • Publicar Web App.
  • Documentar endpoints.

Fase 3 – Frontend conectado

  • Migrar a React + Vite + TS + Tailwind.
  • Conectar fetch al backend.
  • Implementar módulos: Dashboard, Productos, Alertas.
  • Implementar exportación PDF/Excel.

Fase 4 – Módulos completos

  • Cronograma, MEL, Beneficiarios, Finanzas, Instituciones, Talento Humano.
  • Panel de administración con contraseña.
  • Formularios de carga y edición.

Fase 5 – Pruebas y ajustes

  • Pruebas funcionales con datos reales.
  • Pruebas de rendimiento.
  • Corrección de bugs.
  • Validación con el equipo CEPE.

Fase 6 – Despliegue y capacitación

  • Publicación final en GitHub Pages.
  • Manual de usuario (PDF).
  • Capacitación al equipo.
  • Entrega formal.

Fase 7 – Mantenimiento

  • Soporte y mejoras continuas.
  • Actualizaciones mensuales.
  • Respaldos automáticos.
